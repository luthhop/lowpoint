# Decisões
- Stack de IA: Claude Code + Paper + Obsidian; Codex autorizado como apoio em 2026-11-05 durante os limites de uso do Claude. Ambos consultam o mesmo vault memoria/.
- MVP: bot Telegram pessoal, só Mercado Livre. Comandos /adicionar /lista /remover, alerta de preço-alvo, histórico de preços
- Stack MVP: Python + python-telegram-bot + PostgreSQL (Neon cloud) + SQLAlchemy 2 + Alembic
- Banco: Neon (cloud) para produção e coleta contínua. Docker Compose mantido como opção para dev local. DATABASE_URL no .env com SSL obrigatório
- Tipos monetários: NUMERIC(12,2) no banco, Decimal no Python. Nunca float
- Datas: TIMESTAMPTZ no banco, exibição America/Sao_Paulo
- Prazo: núcleo funcionando antes da Black Friday (2026-11-27), monitorar 2 produtos reais
- Plano de sprints: S1 (08/11) dados+coletor | S2 (15/11) bot Telegram | S3 (22/11) veredito+testes+24/7 | pós-BF telas/deploy
- Corte de escopo, não de qualidade: testes desde o início são obrigatórios
- Coleta de preços: 1h normal, 15-30min de 23 a 27/11 (Black Friday). Multiget /items?ids= até 20 IDs por chamada
- DESCOBERTA (2026-11-02): /sale_price, /prices, /items, /search retornam 403 para anúncios de terceiros. MAS /products/{id}/items retorna 200 com price, original_price, seller_id, item_id, condition, official_store_id, shipping
- Scraping descartado: viola cláusula 7.6 dos Termos de Desenvolvedores e o projeto será público. Serviços terceiros de scraping também descartados
- Fonte de preço MVP: /products/{id}/items (endpoint de catálogo). Só links de catálogo (/p/MLB...) aceitos. Links de anúncio avulso: bot avisa que precisa ser link de catálogo
- Interface PriceSource aprovada: ABC desacoplando fonte de preço do resto do sistema. MLCatalogSource para MVP, Amazon Creators API para Fase 2
- Tabela offer_snapshots: todas as ofertas de cada coleta. price_history guarda a melhor oferta (derivada)
- Melhor oferta: menor preço entre ofertas new não-suspeitas. Loja oficial é desempate (mesmo preço), não filtro. Avisos: vendedor não-oficial, sem garantia, ofertas suspeitas
- Proteção contra golpe: ofertas com preço < 60% da mediana da coleta são suspeitas e excluídas da melhor oferta (threshold configurável). Lowpoint protege contra golpe, não só contra desconto maquiado
- "Sem garantia" (string da API ML) tratado como ausência de garantia para fins de aviso e require_warranty
- Disponibilidade: produto disponível = existe pelo menos 1 oferta válida na coleta
- Veredito: função pura em módulo próprio. Limites configuráveis (5%, 10%, 7d, 14d). Todo alerta carrega veredito
- Maquiado: original_price > mediana_30d * 1.10 OU preço subiu >10% nos 14d antes da queda
- Excluir coletas com available=false de todos os cálculos de veredito
- Fase 2: site com landing page + painel, design no Paper, publicar GitHub/LinkedIn
- Direção visual: Signage (editorial) + Onyx (disciplina brutalista). Preto e tipo fazem o trabalho
- Cor de acento: Forest #1B6B3A — só desconto verificado como real. Verde é conquistado, não decorativo
- Ocre #7A5A10 só para veredito "segura" (maquiado). Sem vermelho em lugar nenhum
- Tipografia: Archivo 900 (display, uppercase), Libre Franklin 400/600 (corpo), IBM Plex Mono 500/700 (dados/preços)
- Radius 0, sem gradientes, sem glassmorphism, sem Inter, sem amarelo/laranja/roxo gradiente
- Fluxo de design: toda tela é desenhada no Paper (seguindo branding board) → aprovação do Lucas → implementação. Nenhuma tela sem design aprovado
- Telas previstas (Fase 2): landing page, login/cadastro, onboarding (conectar Telegram), dashboard, mensagens do bot
- Logo: wordmark "LOWPOINT." (Archivo Black 900 + ponto Forest). Duplo sentido: ponto = point + ponto final
- Avatar Telegram: monograma "L." branco sobre círculo Ink, ponto Forest
- Elemento secundário: ponto Forest isolado em círculo Ink — usar em favicon, loading, hero SVG
- API real: campo do item é "item_id" (não "id") e /products/{id}/items não retorna title/thumbnail. Título e imagem vêm de /products/{id} (campo "name" e "pictures")
- Registro de produto: lowpoint/register.py (CLI sem bot). Aceita --url ou --catalog-id + --target
- Coletor: lowpoint/collect.py. --once (ciclo único) ou --interval N (padrão 3600s). Um produto falhando não bloqueia os outros
- Bot Telegram: alertas enviados pelo coletor (GitHub Actions, via API Telegram). Comandos via webhook numa função serverless Vercel (Python, plano Hobby)
- Segurança webhook: secret_token validado no header X-Telegram-Bot-Api-Secret-Token + allowlist de chat_id (ALLOWED_CHAT_IDS). Estranhos recebem mensagem educada
- Anti-spam de alertas: mesmo tipo de alerta reenviado só se preço cair abaixo do último alerta enviado para aquele watch
- Ofertas suspeitas: sem alerta próprio, viram rodapé nos outros alertas. "Sem garantia" é aviso de destaque; "vendedor não-oficial" discreto
- /remover e escolhas usam inline buttons (callback_query), sem estado de conversa no webhook
- /adicionar aceita apelido opcional; sem apelido, usa título do produto
- Target hit com histórico curto (<7 dias): alerta com 🎯 sem afirmar desconto real. Maquiado prevalece sobre neutro
- /adicionar grava PriceHistory na hora para /lista mostrar "Agora:" imediatamente
- Filtro anti-golpe com fallback: quando coleta traz < 3 ofertas, usa mediana histórica (price_history) para detectar suspeitas. Sem histórico E < 3 ofertas = sem filtro (produto novo)
- Coleta anômala: se ofertas < 30% da mediana das últimas 10 coletas, dados gravados mas alertas suprimidos. Mínimo 3 coletas anteriores para ativar detecção
- Footer com aviso "poucos vendedores" quando < 3 ofertas na coleta (qualquer tipo de alerta)
- Feed geral de promoções: fora do MVP e da Fase 2. ML /search retorna 403; Amazon depende de vendas como afiliado. Sem fonte viável agora
- Amazon Creators API: Fase 2 como segundo PriceSource. Links de afiliado nos botões "Ver oferta" (comissão nunca influencia o veredito). Requer conta Amazon Associates com vendas ativas
- Login do dashboard: Telegram OIDC (OAuth 2.0 Authorization Code + PKCE). ID token com claim `sub` = user ID do Telegram. Scope `telegram:bot_access` permite bot enviar DMs após login. Widget legado com hash existe mas OIDC é o padrão atual
- Fix _detect_hike (2026-11-05, consolidado): pico detectado usa preço pré-pico como baseline limpo, preservando median_30d real. Desconto >3% segue as regras normais: ≥5% e menor histórico = real; caso contrário neutro. Formatter mostra markup do pico (ex: 74%) no SEGURA.
- "Menor preço desde que começamos a monitorar" (2026-11-05): substitui "menor preço em N dias" quando N = total do histórico. Motivo: N arbitrário confunde; "desde que começamos" é mais honesto
- "Preço riscado" em vez de "O anúncio diz X% OFF" (2026-11-05): mostra o preço riscado original + % calculado com floor(). Motivo: "o anúncio diz" pressupõe que a % vem do anúncio, mas calculamos nós mesmos. Floor evita arredondar pra cima e parecer mais desconto do que é
- "há N dias" em vez de "em N dias" (2026-11-05): hike_days conta do primeiro ponto elevado até hoje, não até o pico. "há" é mais preciso
- baseline_price separado de median_30d (2026-11-05): median_30d = mediana real dos 30 dias (pode estar contaminada pelo hike). baseline_price = pre_hike_price quando hike detectado, median_30d caso contrário. Formatter usa baseline_price para "preço normal"
- FACHADA_THRESHOLD = 3% (2026-11-05, corrigido): desconto ≤3% do pré-pico continua maquiado; >3% sai do SEGURA e segue a lógica normal sobre baseline_price. Preço riscado inflado não veta essa recuperação; sem pico, a regra de original inflado permanece. Nota: "Inflaram antes, mas mesmo assim tá X% abaixo do preço normal."
- Validação pós-pico (2026-11-05): 4% = neutro (alerta só com alvo atingido), 10% e 20% = real se menor histórico. Simulação local reproduzível e textos em design/validacao-pos-pico.md; nenhuma mensagem real ou gravação em produção.
- Landing (2026-11-05): Lucas aprovou abertura A (investigação editorial) + desfecho B (ponto mais baixo, fundo Ink). Gráfico com traço fluido, mantendo o histórico como evidência; fluxo e pendências em design/landing-fluxo-consolidado.md. Aprovação da direção não libera implementação das seções ainda não desenhadas.
- Frontend (2026-11-05): Lucas aprovou todas as seções; implementação local em frontend/ com React + TypeScript + Vite, CSS próprio, SVG e movimento nativo. Fontes locais; valores em centavos; fixture verificado contra o veredito Python.
- Publicação frontend: separar a landing estática do webhook Vercel existente. Acesso atual pessoal informado na página, CTA para GitHub; nenhum cadastro público ou integração nova com produção nesta etapa.

- Publicação autorizada por Lucas (2026-11-05): landing em https://lowpoint-web.vercel.app, projeto Vercel `lowpoint-web` separado do webhook `lowpoint`; GitHub conectado com raiz `frontend`, Node 26.x, npm ci/build e dist. Acesso público verificado.
- SEGURA template C (2026-11-10, Lucas): com pico detectado volta "O anúncio diz X% OFF (de R$ …)" e "Subiram X% em N dias" (N do início do pico até hoje). Reverte, só nesse template, as decisões de 05/11 "Preço riscado" e "há N dias"; SEGURA sem pico mantém "Preço riscado". Nunca diferença negativa: abaixo do pré-pico vira "Tá só X% abaixo…"; empate ou <1% vira "Voltou ao preço de antes".
- Faixas pós-pico (2026-11-10, Lucas; desconto vs. pré-pico): ≤3% = fachada (maquiado/SEGURA); >3% e <5% = neutro (MONITORANDO, só envia com alvo atingido); ≥5% = real se também for o menor preço do histórico, senão neutro. Limite é ≥5% (REAL_DISCOUNT_THRESHOLD), coberto por teste em 0.05.
- Coleta via /api/tick (2026-11-10, Lucas): cron externo chama POST /api/tick a cada 15 min (header X-Tick-Secret, hmac). Tick dispara workflow_dispatch do collect.yml: sempre em 23–27/11 (horário de Brasília), fora disso só se a última coleta tiver >55 min. Cron do GitHub (:17) fica como reserva; concurrency lowpoint-collect sem cancelamento.
- Aviso de coleta atrasada: última coleta = max(offer_snapshots.collected_at), que só o coletor grava. >90 min → Telegram para o 1º ALLOWED_CHAT_IDS, no máximo 1 por hora (marcador em system_state).
- Chamadas ao ML: timeout (5s, 15s), até 3 tentativas com backoff 1s/2s em 429, 5xx e falha de rede; Retry-After respeitado até 10s.
- Textos (2026-11-10): nota pós-pico "Subiram antes, mas mesmo assim tá X% abaixo do preço normal" (casa com template C); MONITORANDO mostra o motivo como frase própria, sem "Preço atual.".
